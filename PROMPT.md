Build a Claude Code status line that shows the plan usage limits, so the limit is visible before it hits.

- Data: Claude Code sends the status line command a JSON payload on stdin. Use ONLY the rate_limits field: rate_limits.five_hour and rate_limits.seven_day, each with used_percentage (0 to 100) and resets_at (Unix epoch seconds). Read nothing else from the payload: no cwd, paths, session id, model, cost or context.
- Output: one line, like
  5h 23% · resets 3:40pm   week 41% · resets Mon 3am
  Whole percent, rounded to the nearest. Reset as a local clock time in Claude Code's own style (3am, 3:40pm); add the weekday when the reset is more than 24 hours away. Color only the percent: green under 50, yellow 50 to 79, red 80 and up.
- Be honest when data is missing: rate_limits only appears after the first reply of a session, and each window can be absent. Print "5h --" or "week --" for a missing window, never 0%. Treat a window whose resets_at has already passed as missing.
- Never break the status line: always exit 0 and always print a line, even on empty or malformed input. If jq is missing, print "limits: jq not found" instead of failing. Keep it fast.
- No network calls, no estimates or projections, no reading any file or credential. stdin only.
- Must work on a stock Mac: bash 3.2 and BSD date (date -r). Fall back to GNU date -d on Linux.
- Files: statusline.sh, a project .claude/settings.json with a statusLine entry pointing at it (type "command"), an install.sh that adds the statusLine entry to the user's ~/.claude/settings.json without clobbering other settings (backup first, re-running adds nothing, an existing different statusLine is left alone with a message saying how to switch), and an uninstall option that removes only this entry.
- Tests: tests/run_tests.sh that pipes at least 12 saved fixture payloads through statusline.sh and checks the exact output. Write the fixtures yourself: both windows; a decimal percent (23.5); 0; 100; only five_hour; only seven_day; no rate_limits at all (fresh session); rate_limits null; a reset already passed; malformed JSON; a full payload with every other documented field filled in (assert none of it leaks into the output); the color thresholds at 49, 50, 79 and 80. Set TZ=UTC inside the tests so they pass anywhere. Test install.sh only against a throwaway fake HOME: existing settings kept, backup made, second run adds nothing, uninstall leaves other settings intact. Never touch the real ~/.claude. Run the tests in the foreground and wait for them.
- README: what it shows, install, uninstall, and a short "What it can't show" section (model-specific limits such as the weekly Fable limit on Max, nothing before the first reply, Pro and Max plans only, whole percents as of the last reply, not in claude -p or the VS Code panel).
